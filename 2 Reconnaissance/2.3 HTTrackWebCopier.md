# HTTrack: Detailed Notes

## 1. Overview

**HTTrack** is a free, open-source (GPL) website copier ("offline browser"). It downloads a site's HTML, images, CSS, JS, and other files into a local folder and **rewrites links** so the copy can be browsed offline.

- **Platforms:** Windows (WinHTTrack), Linux/macOS/BSD (WebHTTrack GUI in a browser, plus the `httrack` CLI).
- **Typical uses:** backing up your own site, archiving content, offline reading, migrating or auditing a site, and analyzing site structure.
- **Limitation:** it fetches static responses. Content rendered by JavaScript (SPAs, React/Vue apps, infinite scroll) is often missed.

## 2. Installation

| Platform | Command / method |
|---|---|
| Debian/Ubuntu | `sudo apt install httrack webhttrack` |
| Fedora/RHEL | `sudo dnf install httrack` |
| macOS | `brew install httrack` |
| Windows | Installer from httrack.com (WinHTTrack) |

## 3. Basic Usage

**GUI (WinHTTrack / WebHTTrack) flow:**
1. Name the project and choose a category and base path.
2. Choose the action: *Download web site(s)*, *Update existing download*, *Continue interrupted download*, etc.
3. Enter URLs, then use *Set options* for filters and limits.
4. Start. Logs appear in the project folder.

**CLI basics:**
```
httrack "https://example.com/" -O "/path/to/mirror"
```
- `-O` sets the output path (mirror, cache, and logs).
- Quote URLs and filters so the shell doesn't expand `*`.

## 4. Key Options (CLI)

**Scope (where it may go)**

| Option | Meaning |
|---|---|
| `-a` | Stay on the same address (default) |
| `-d` | Stay on the same principal domain |
| `-l` | Stay on the same TLD |
| `-e` | Go everywhere on the web |
| `-S` | Stay in the same directory |
| `-D` | Only go down into subdirectories (default) |
| `-U` | Only go up |
| `-B` | Both up and down |
| `-rN` | Mirror depth (e.g., `-r3`) |
| `-%eN` | External-link depth |

**Speed and politeness (important)**

| Option | Meaning |
|---|---|
| `-cN` | Simultaneous connections (default 8; lower for small servers, e.g., `-c2`) |
| `-%cN` | Max connections per second |
| `-AN` | Max transfer rate in bytes/sec |
| `-%SN` | Wait N seconds between requests (used with `-%c` etc.; check `httrack --help` for your version) |
| `-TN` | Timeout in seconds |
| `-RN` | Retries on failure |
| `-EN` | Max mirror time in seconds |
| `-MN` | Max total size in bytes |
| `-mN` | Max size of non-HTML files |

**Links and structure**

| Option | Meaning |
|---|---|
| `-K0` | Relative links (default, best for offline browsing) |
| `-K` | Absolute links |
| `-K4` | Keep original links |
| `-N#` | Site structure type (`-N1` = html/images folders, etc.) |
| `-n` | Also fetch non-HTML files near an HTML page |
| `-t` | Test all URLs, even ones that would be skipped |
| `-%P` | Extended parsing (attempts to find links in JS/CSS) |
| `-x` | Replace external links with an error page |

**Identity and behavior**

| Option | Meaning |
|---|---|
| `-F "UA string"` | Set the User-Agent |
| `-s0/-s1/-s2` | robots.txt handling: `0` ignore, `1` follow sometimes, `2` always follow (default) |
| `-b0/-b1` | Cookies off/on |
| `-C0/1/2` | Cache mode |
| `-%v` | Show file names while downloading |
| `-q` / `-Q` | Quiet / no questions |

## 5. Filters (Scan Rules)

Filters are `+` (include) and `-` (exclude) patterns using `*` wildcards. Later rules override earlier ones.

```
httrack "https://example.com/" -O ./mirror \
  "+*.example.com/*" \
  "-*.zip" "-*.mp4" \
  "+*.css" "+*.js" "+*.png" "+*.jpg"
```

Common patterns:
- `-*/admin/*` skips a section.
- `+*cdn.example.com/*` allows assets on a CDN domain (needed when images/CSS live off-domain).
- `-*?*` skips URLs with query strings (avoids endless dynamic pages).
- Order matters: put broad excludes first, specific includes after.

## 6. Updating and Resuming

| Task | How |
|---|---|
| Update an existing mirror | `httrack --update` (or `-i` variants) in the project dir |
| Continue an interrupted run | `httrack --continue` (`-i`) |
| Re-run same project | GUI: *Update existing download* |

HTTrack uses its **cache** (`hts-cache/`) to fetch only changed files.

## 7. Output Structure

```
mirror/
├── index.html          ← project index page
├── example.com/        ← mirrored site
├── hts-cache/          ← cache, needed for updates/continues
├── hts-log.txt         ← errors and warnings
└── cookies.txt         ← saved cookies (if enabled)
```
Keep `hts-cache/` if you plan to update. Check `hts-log.txt` for missing files and blocked URLs.

## 8. Troubleshooting

| Problem | Likely fix |
|---|---|
| Only the homepage downloads | Filters too strict, robots blocked, or links are JS-generated |
| Missing images/CSS | Assets on another domain; add `+` filters for that host |
| Site loads forever or downloads huge amounts | Reduce depth `-rN`, exclude query strings, set `-M` / `-E` limits |
| HTTP 403/429 errors | Server is rate limiting; lower `-c`, add delays, slow `-A` |
| Broken links offline | Try `-K0`, check `-N` structure, re-run with `-%P` |
| Login-required content | Mirroring behind auth is unreliable; use exported cookies (`cookies.txt`) only on accounts and sites you're authorized for |
| JS-rendered pages empty | Use a headless-browser tool (e.g., SingleFile, ArchiveBox) instead |

## 9. Legal and Ethical Use

- Copy only sites you **own or have permission** to copy. Content is usually copyrighted, and terms of service may prohibit scraping.
- **Be polite:** use low connection counts and rate limits, and avoid running during peak hours.
- Respect `robots.txt` (`-s2`, the default). Overriding it with `-s0` doesn't grant permission and may violate a site's terms or laws.
- Don't use mirrors to redeploy someone else's site (phishing/clone sites are illegal).

## 10. Defensive Notes (For Site Owners)

HTTrack identifies as `HTTrack` in its default User-Agent, so it's easy to detect in logs. Owners can:
- Rate-limit per IP (e.g., Nginx `limit_req`, fail2ban, WAF rules).
- Block or challenge unwanted crawlers (though User-Agents are easily changed, so behavioral limits are more reliable).
- Monitor for unusually high request rates and sequential page fetching.

## 12. Quick Reference Commands

```
# Basic mirror
httrack "https://example.com/" -O ./mirror

# Polite mirror (low load, depth-limited)
httrack "https://example.com/" -O ./mirror -r4 -c2 -%c1 -A100000 "+*.example.com/*"

# Skip big media files
httrack "https://example.com/" -O ./mirror "-*.mp4" "-*.zip" "-*.iso"

# Update an existing mirror
cd ./mirror && httrack --update

# Resume an interrupted mirror
cd ./mirror && httrack --continue
```
