# Google Search Operators: Detailed Notes

## 1. Core Search Operators (Directives)

**Syntax rule:** operator, colon, then the term, with no space after the colon. `site:abc.com` works, `site: abc.com` may not.

| Operator | What it does | Example |
|---|---|---|
| `site:` | Limits results to one domain, subdomain, or TLD | `site:abc.com`, `site:.edu`, `site:blog.abc.com` |
| `intitle:` | Word/phrase must be in the page's `<title>` | `intitle:"annual report"` |
| `allintitle:` | *All* listed words must be in the title | `allintitle: budget 2026 report` |
| `inurl:` | Keyword must appear in the URL | `inurl:login` |
| `allinurl:` | All listed words must be in the URL | `allinurl: admin panel` |
| `intext:` | Keyword must appear in the body text | `intext:"contact us"` |
| `allintext:` | All terms must be in the body text | `allintext: username password policy` |
| `filetype:` / `ext:` | Filters by file extension | `filetype:pdf`, `ext:xlsx` |

**Practical notes**
- `intitle:` and `intext:` apply only to the *next* word or quoted phrase. In `intitle:annual report`, "report" is searched anywhere on the page. Use quotes or `allintitle:` to bind more words.
- `allin...:` operators apply to the whole query and generally **can't be combined** with other operators. Chaining several `intitle:` or `inurl:` operators is usually more flexible.
- Common `filetype:` values: `pdf`, `docx`, `xlsx`, `pptx`, `csv`, `txt`, `log`, `xml`, `sql`.
- `site:` alone with no keyword lists roughly what Google has indexed for that domain, which is useful for a quick footprint check.

## 2. Modifiers & Punctuation

| Modifier | Function | Example |
|---|---|---|
| `" "` | Exact phrase match | `"open directory listing"` |
| `-` | Excludes a term or operator (no space between `-` and the term) | `jaguar -car`, `-site:wikipedia.org` |
| `OR` (or `\|`) | Either term; **OR must be uppercase** | `pdf OR docx` |
| `*` | Wildcard for one or more unknown words, mainly inside phrases | `"how to * a website"` |
| `AROUND(X)` | Two terms within X words of each other | `security AROUND(4) audit` |
| `before:` / `after:` | Date filters (`YYYY`, `YYYY-MM`, or `YYYY-MM-DD`) | `after:2025-01-01 before:2026-01-01` |
| `( )` | Groups terms for logic | `site:abc.com (filetype:pdf OR filetype:docx)` |

**Practical notes**
- Operators are case-insensitive except `OR`.
- Quotes make matching stricter, but Google may still normalize minor variations. Results are not guaranteed to be verbatim.
- `AROUND(X)` is sensitive to word order only loosely, so it works well for finding two concepts in the same passage.
- Google has retired some older operators (e.g. `cache:`, `+`, `related:`), so results vary. Test what still works.
- Combine freely: `site:abc.com filetype:pdf -inurl:archive after:2024`.

## 3. Open Directories (`intitle:"index of"`)

**What it is**
When a web server has *directory listing* (autoindex) enabled and a folder has no default page (`index.html`, etc.), the server auto-generates a page titled "Index of /foldername" showing the raw file tree. Google indexes these like any page, so `intitle:"index of"` surfaces them.

**Using it on a specific site**
```
site:abc.com intitle:"index of"
```
Finds indexed directory listings on that domain.

**Refined variations**
```
site:abc.com intitle:"index of" filetype:pdf
site:abc.com intitle:"index of" "parent directory"
site:abc.com intitle:"index of" (backup OR logs OR uploads)
```

**Appropriate use:** audit only domains you own or are authorized to assess (your own site, an employer's, or a scoped engagement). Search results show only what's already publicly indexed, but accessing or using exposed files that aren't meant to be public can carry legal and ethical consequences.

**Why it matters (risk)**
Exposed listings can leak backups, config files, logs, internal documents, and uploads, sometimes containing credentials or personal data.

**Fixing exposed directories (defensive checklist)**
1. **Disable directory listing**
   - Apache: `Options -Indexes` (in `.htaccess` or the vhost config)
   - Nginx: `autoindex off;`
   - IIS: disable "Directory Browsing"
2. **Add a default index file** in folders that must stay web-accessible.
3. **Move sensitive files** outside the web root, or put them behind authentication.
4. **Remove already-indexed pages**: use Google Search Console's Removals tool, and use `noindex` headers or a 404/410 once fixed.
5. **Don't rely on `robots.txt`**: it isn't access control and can actually advertise sensitive paths.
6. **Re-audit periodically** with the same queries.

## 4. Quick Reference: Combined Query Patterns

```
site:abc.com filetype:pdf                        → all indexed PDFs on the site
site:abc.com -inurl:blog                         → exclude the blog section
site:abc.com intitle:"index of"                  → exposed directory listings
site:abc.com inurl:login OR inurl:admin          → login/admin pages that are indexed
"annual report" filetype:pdf after:2025          → recent PDFs with the phrase
intitle:"index of" "parent directory" site:.edu  → listings across a TLD
```

## 5. Key Takeaways
- Operators narrow results by **where** a term appears (title, URL, body, file type, site, date).
- Modifiers control **how** terms are matched (exact, excluded, alternative, proximity).
- `intitle:"index of"` is a well-known way to spot misconfigured servers, and the same query is a valuable **defensive audit** tool for your own domains.
