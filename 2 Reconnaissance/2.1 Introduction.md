
# Reconnaissance: Introduction (Detailed Notes)

## 1. What Is Reconnaissance?

**Reconnaissance** (also called *footprinting* or *information gathering*) is the first phase of a security assessment or attack lifecycle. The goal is to collect as much information as possible about a target organization, system, or network **before** any exploitation is attempted.

- **Military origin:** scouting an area before an operation.
- **Security context:** building a profile of a target's people, technology, network layout, and exposure.
- **Core idea:** the more you know about a target, the more precisely you can assess its attack surface.
- **Both sides use it:** attackers use it to plan, and penetration testers and defenders use it to see what an attacker would see.

## 2. Where It Fits in the Attack Lifecycle

| Phase | Purpose |
|---|---|
| **1. Reconnaissance** | Gather information about the target |
| 2. Scanning & Enumeration | Identify live hosts, open ports, services, users, shares |
| 3. Gaining Access | Exploit weaknesses found earlier |
| 4. Maintaining Access | Persistence (backdoors, accounts) |
| 5. Covering Tracks | Log clearing, evasion |
| 6. Reporting (in authorized tests) | Document findings and remediation |

Frameworks that include recon as an early stage:
- **Lockheed Martin Cyber Kill Chain:** Reconnaissance → Weaponization → Delivery → Exploitation → Installation → C2 → Actions on Objectives
- **MITRE ATT&CK:** Reconnaissance (TA0043) is the first tactic
- **PTES / OSSTMM / NIST SP 800-115:** all include information-gathering phases

## 3. Objectives of Reconnaissance

1. **Map the attack surface:** domains, subdomains, IP ranges, exposed services
2. **Identify technologies:** web servers, frameworks, CMS, OS, versions
3. **Discover people and roles:** employees, emails, org structure (social engineering targets)
4. **Find leaked or exposed data:** documents, metadata, credentials, code repositories
5. **Understand the business:** partners, vendors, acquisitions, physical locations
6. **Narrow the scope:** decide where to spend time in later phases

## 4. Types of Reconnaissance

### A. Passive Reconnaissance
Gathering information **without directly interacting** with the target's systems. The target has little or no way to detect it.

**Sources:**
- Search engines (Google operators, Bing, DuckDuckGo)
- WHOIS and DNS records (public registries)
- Certificate transparency logs
- Social media and professional networks (LinkedIn, X, etc.)
- Job postings (reveal tech stack)
- Public code repositories (GitHub, GitLab)
- Web archives (Wayback Machine)
- Breach and paste-site data
- Internet-wide scan databases (Shodan, Censys)
- News, press releases, financial filings

**Pros:** low risk of detection, legally safer
**Cons:** information may be outdated or incomplete

### B. Active Reconnaissance
**Directly interacting** with the target's systems to elicit information. It can be logged and detected.

**Examples:**
- Port scanning and service probing
- DNS queries against the target's own name servers, zone transfer attempts
- Banner grabbing
- Web crawling and mirroring the site
- Vulnerability scanning
- Network mapping (traceroute, ping sweeps)
- Physical or social approaches (calls, visits)

**Pros:** current, detailed, accurate data
**Cons:** detectable (IDS/IPS, logs), may trigger alerts, and **requires authorization**

### Comparison

| Aspect | Passive | Active |
|---|---|---|
| Contact with target | None / indirect | Direct |
| Detection risk | Very low | Moderate to high |
| Data freshness | Variable | Current |
| Authorization needed | Generally less sensitive, but still bound by law and terms of use | **Always, in writing** |
| Example | WHOIS lookup | Port scan |

There is also **semi-passive** recon: activity that looks like normal traffic (browsing the target's public site, standard DNS lookups) and is hard to distinguish from ordinary visitors.

## 5. Categories of Information Collected

| Category | Examples |
|---|---|
| **Organizational** | Company structure, subsidiaries, locations, partners, vendors |
| **Network** | Domains, subdomains, IP ranges (ASNs), name servers, mail servers |
| **System / technology** | OS, web server, frameworks, CMS, WAF, cloud providers, software versions |
| **People** | Names, roles, emails, phone numbers, social profiles, email format |
| **Credentials / secrets** | Leaked passwords, API keys, tokens (in repos, pastes, breaches) |
| **Documents / metadata** | PDFs and Office files revealing usernames, software, internal paths |
| **Physical** | Office addresses, entry points, badge styles, Wi-Fi networks |
| **Security posture** | Email security (SPF/DKIM/DMARC), exposed admin panels, misconfigurations |

## 6. Common Techniques (Conceptual Overview)

- **Search engine and operator queries** (Google dorking): finding indexed files, login pages, exposed directories
- **WHOIS / RDAP:** registrant, registrar, name servers, creation and expiry dates
- **DNS enumeration:** A, AAAA, MX, NS, TXT, CNAME records; subdomain discovery
- **Certificate transparency:** subdomains revealed via issued TLS certificates
- **Website analysis:** technology fingerprinting, `robots.txt`, `sitemap.xml`, HTML comments, JS files
- **Site mirroring** (e.g., HTTrack): offline analysis of site structure and content
- **Metadata extraction:** from public documents and images
- **OSINT on people:** email formats, social media, conference talks
- **Network-level:** ASN and IP range lookups, reverse DNS, traceroute
- **Social engineering recon:** pretexting research (only in authorized engagements)

## 8. Recon Methodology (Typical Workflow)

1. **Define scope and rules of engagement:** targets, allowed techniques, time windows, contacts
2. **Passive collection:** domains, ownership, public footprint
3. **Enumerate assets:** subdomains, IP ranges, cloud resources
4. **Fingerprint technologies:** servers, frameworks, versions
5. **Collect people and contact data:** for awareness or social-engineering assessments if in scope
6. **Search for exposures:** leaked docs, repos, credentials, misconfigurations
7. **Active probing (if authorized):** scanning, banner grabbing, crawling
8. **Organize and correlate:** build an asset inventory and attack-surface map
9. **Document and prioritize:** feed results into scanning and vulnerability analysis

**Tip:** keep organized notes (spreadsheets, Obsidian, CherryTree, Maltego graphs) with source, timestamp, and confidence for each finding.

## 9. Legal and Ethical Considerations

- **Authorization is essential** for anything active. Get a signed scope or rules-of-engagement document.
- Passive OSINT is not automatically risk-free: laws on data protection (GDPR, etc.), terms of service, and computer misuse acts (CFAA, Computer Misuse Act, and local equivalents) may apply.
- Stay in scope. Don't touch third-party assets (cloud providers, partners) unless explicitly authorized.
- Handle personal data responsibly: collect only what is needed, store it securely, and report it appropriately.
- Never use discovered credentials or access exposed data outside the agreed scope. Report exposures instead.
- Bug bounty programs define their own scope, so follow the program policy.

## 10. Defensive Perspective (Reducing Your Footprint)

| Risk | Mitigation |
|---|---|
| Public info leakage | Review what's published: staff details, job ads, docs |
| Document metadata | Strip metadata before publishing |
| Exposed directories / files | Disable directory listing, review indexed content |
| DNS and subdomain sprawl | Maintain asset inventory, remove stale records |
| WHOIS exposure | Use privacy/redaction services |
| Leaked secrets in repos | Secret scanning, rotate keys, pre-commit hooks |
| Verbose banners / errors | Suppress version info and debug output |
| Social engineering | Awareness training, verification procedures |
| Detection | Monitor for scanning patterns, enable alerting, use rate-limiting and WAF |

**Good practice:** run recon against your **own** organization regularly (external attack surface management) to find exposures before others do.

## 11. Connection to Your Earlier Notes

- **Google search operators** (`site:`, `intitle:"index of"`, `filetype:`) are passive recon techniques.
- **HTTrack** is a semi-active/active technique for mirroring and analyzing a site's structure.
- Both are used to build the asset and exposure picture that feeds the next phase, **scanning and enumeration**.

## 12. Key Takeaways

- Reconnaissance is the **foundation** of any security assessment: the quality of later phases depends on it.
- **Passive** = no direct contact, low risk. **Active** = direct contact, detectable, needs authorization.
- The goal is a complete picture of the **attack surface**: people, technology, network, and data exposure.
- Always operate **within scope and the law**.
- Defenders benefit by running the same recon on themselves.
